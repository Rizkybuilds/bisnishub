# MGBOS 0.5.4

## Repository Bootstrap Specification v0.1

## 1. Tujuan

Tahap ini menghasilkan repository MGBOS yang:

- dapat dijalankan developer lokal;
    
- mempunyai database lokal reproducible;
    
- mempunyai CI;
    
- mempunyai environment validation;
    
- mempunyai authentication foundation;
    
- mempunyai struktur modular;
    
- mempunyai documentation baseline;
    
- siap menerima issue bisnis pertama tanpa perlu mengubah arsitektur fundamental.
    

Target akhir tahap ini:

```text
git clone
↓
pnpm install
↓
Supabase start
↓
pnpm dev
↓
Login
↓
MGBOS shell
```

Developer atau coding agent baru harus dapat menjalankan project berdasarkan README tanpa pengetahuan tersembunyi.

# 18. Dependency Policy

# 71. ORM Decision

Untuk bootstrap, jangan memilih ORM hanya karena vibe coding lebih mudah.

Karena Supabase/PostgreSQL already provide strong tooling, keputusan ORM/query builder harus didasarkan kebutuhan.

Baseline architecture tidak membutuhkan ORM sebagai architectural dependency.

Kalau nanti kita memilih Drizzle/Prisma/SQL-oriented access, keputusan itu dicatat sebagai ADR.

Artinya **jangan menambah ORM dalam MGBOS-001 tanpa kebutuhan implementasi yang jelas.**
