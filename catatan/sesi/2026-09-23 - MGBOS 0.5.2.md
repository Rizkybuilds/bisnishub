# MGBOS 0.5.2

## TeeStock Custom Atelier — Implementation Backlog & Build Plan v0.1

## 1. Tujuan

Dokumen ini menerjemahkan Product Specification MGBOS 0.5.1 menjadi **urutan implementasi yang dapat dieksekusi**.

Prinsip utamanya:

> Jangan membangun layer demi layer sampai berbulan-bulan sebelum ada sesuatu yang bisa dipakai.

Kita membangun dalam **vertical slices**.

Setiap slice idealnya menghasilkan fungsi bisnis yang sudah bisa diuji dari UI sampai database.

Target akhirnya:

```text
Real Inquiry
→ Real Lead
→ Real Requirement
→ Real Quote
→ Real Order
→ Real Payment
→ Real Production
→ Real Vendor
→ Real QC
→ Real Fulfillment
→ Real Margin
```

---

# 2. Engineering Principles

Seluruh implementasi harus mengikuti aturan berikut.

### Rule 1 — Small Vertical Slice

Jangan:

```text
Build seluruh database
↓
Build seluruh backend
↓
Build seluruh frontend
```

Lebih baik:

```text
Customer database
+
Customer domain
+
Customer UI
+
Tests
=
DONE
```

kemudian lanjut.

---

### Rule 2 — Domain Rule Before UI Convenience

UI tidak boleh mengubah critical state langsung.

Contoh salah:

```text
Update order.status = ACTIVE
```

Benar:

```text
ActivateOrder command
↓
Validate guards
↓
Transition
↓
Event
```

---

### Rule 3 — Every Slice Must Be Testable

Setiap feature harus memiliki:

- happy path
    
- invalid path
    
- authorization check jika relevan
    
- persistence test
    
- business-event test jika relevan
    

---

### Rule 4 — No Premature AI

AI hanya masuk setelah canonical flow berjalan manual.

---

### Rule 5 — No Premature Automation

Automation hanya dibangun setelah event yang menjadi trigger sudah reliable.

---

### Rule 6 — Every Migration Is Version Controlled

Tidak ada schema production yang hanya hidup di dashboard.

---
