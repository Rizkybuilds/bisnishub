# MGBOS 0.5 — TeeStock Pilot MVP

Sekarang kita berhenti mendesain sistem secara abstrak dan mulai menentukan **produk pertama yang benar-benar dipakai untuk menjalankan bisnis**.

Pilot pertama:

> **TeeStock → Custom Atelier → inquiry sampai transaksi selesai.**

Target 0.5 bukan membuat semua fitur TeeStock. Targetnya adalah membuktikan bahwa satu order nyata bisa berjalan melalui MGBOS tanpa spreadsheet sebagai sumber kebenaran utama.

---

# 0.5.42 — Apa yang sebenarnya sedang kita bangun

Kalau kita zoom out, TeeStock Custom Atelier bukan hanya MVP TeeStock.

Dia menjadi **reference implementation MGBOS**:

```text
Custom Apparel
      ↓
Canonical Commercial Engine
      ↓
Canonical Production Engine
      ↓
Canonical Vendor Engine
      ↓
Canonical Finance Engine
```

Setelah itu MultiGraph bisa reuse:

```text
Lead
Requirement
Quote
Order
Vendor
Production
QC
Finance
```

NeoPack juga.

Squeegee juga.

Yang berubah terutama:

```text
catalog
specification
production methods
pricing rules
vendor capabilities
```

bukan operating system-nya.

# Keputusan berikutnya: MGBOS 0.5.1

Sekarang saya **belum akan langsung coding**.

Tahap yang paling tepat berikutnya adalah membuat **TeeStock Custom Atelier Product Specification** yang sangat konkret.

Kita definisikan:

```text
Customer Journey

Internal User Journey

Exact Screens

Exact Fields

Business Rules

Requirement Schema

Quotation Formula

Payment Terms

Production Workflow

QC Checklist

Vendor Selection Rules

Events

Automations

Acceptance Criteria
```

Itu akan menjadi **PRD + functional specification pertama MGBOS**.

Setelah 0.5.1 selesai, baru kita bisa mengubahnya menjadi **implementation backlog dan GitHub issues** tanpa meminta coding agent menebak-nebak apa yang sebenarnya harus dibangun.
